# 知径 · 项目策划案

## 1. 项目概述

### 1.1 项目名称

知径

### 1.2 项目定位

输入一个想学习的话题，知径从知乎社区中检索高质量内容，并将内容组织成一张具有学习顺序的知识地图。

### 1.3 核心主张

知径不生产新的知识内容，而是完成两件事：

1. 用直答生成“应该先学什么、再学什么”的知识结构。
2. 用知乎搜索结果、赞同数、评论数和作者权威信息确定资源展示权重。

AI 负责结构编排，社区数据负责内容排序，两者共同形成可解释的学习路径。

## 2. 用户与场景

### 2.1 目标用户

- 对某个领域有兴趣，但不知道从哪里开始的泛兴趣学习者。
- 想把搜索结果整理成学习顺序的学生、职场人和自学者。
- 希望快速了解一个新领域全貌，再选择深入方向的人。

### 2.2 典型场景

- “我想学微积分，但不知道极限、导数、积分应该怎样安排。”
- “我想入门摄影，希望先掌握曝光，再理解构图和器材。”
- “我想学 Python，需要一条从语法到项目实践的路径。”

### 2.3 用户痛点

1. 搜索结果是平铺列表，缺乏前置知识和学习顺序。
2. 优质内容分散在回答、文章和专栏中，筛选成本高。
3. 仅看点赞量容易被热门内容误导，无法同时兼顾相关性和讨论质量。
4. 用户开始学习后缺少轻量的进度反馈。

## 3. 产品价值

### 3.1 对用户

- 更快建立领域认知框架。
- 按难度循序学习，减少无效搜索。
- 直接进入知乎原文，不改变用户熟悉的阅读场景。
- 通过“已学”状态保留学习进度。

### 3.2 对知乎生态

- 为社区已有优质内容提供新的发现和分发入口。
- 让高质量回答在主题学习场景中被重新组织。
- 不复制文章全文，不替代原内容消费。

## 4. 产品原则

1. **先给结构，再给资源**：用户首先看到学习地图，而不是搜索结果堆叠。
2. **排序可解释**：相关性由知乎搜索保证，社区互动数据影响展示权重。
3. **等待过程可见**：大纲完成后先展示骨架，资源逐节点加载。
4. **失败真实可恢复**：单个节点失败不影响整张地图，用户可以单独重试。
5. **核心体验不依赖账号**：用户无需登录即可完成生成、阅读和本地进度记录。
6. **服务端保护凭证**：知乎密钥只在服务端使用。

## 5. 产品范围

### 5.1 首版必须完成

- 首页与三个预生成话题入口。
- 自定义话题输入。
- 直答生成学习大纲。
- 知乎资源并发检索与排序。
- React Flow 知识地图。
- 知识点资源卫星圈展开。
- 跳转知乎原文并记录已学状态。
- 一级下钻与面包屑返回。
- 浏览器 localStorage 本地进度。
- 节点级重试、空结果、额度耗尽等降级状态。
- CloudBase 或验证后的可用部署环境。

### 5.2 明确后置

- 节点编辑、自由建图和协作。
- 笔记、批注、收藏和双链。
- 多地图管理。
- 从知乎收藏夹反向生成地图。
- 移动端专门交互。

## 6. 竞争与差异化

知径与普通搜索的差异是提供学习顺序，与课程平台的差异是使用知乎社区内容而不是自建课程，与知识管理工具的差异是从“一个问题”即时生成地图。

首版差异化集中在三点：

- 知识结构是可探索的地图，而不是长列表。
- 资源排序同时考虑知乎相关性和社区互动。
- 资源加载过程可视化，用户能看到地图从骨架变完整。

## 7. 运营与内容策略

### 7.1 首发预生成话题

- 微积分
- Python 入门
- 摄影

选择标准：领域认知层次清楚、知乎内容丰富、视觉演示效果好、能覆盖不同类型的学习需求。

### 7.2 质量控制

- 预生成地图上线前人工检查节点顺序、边关系和资源相关性。
- 实时生成仅承诺“尽力提供可用地图”，不承诺所有话题都能生成完整资源。
- 对金融、医疗、法律等高风险话题展示风险提示，并建议以官方信息和专业意见为准。

## 8. 技术与成本策略

### 8.1 调用策略

- 每张地图默认 1 次直答调用和每节点 1 次知乎搜索。
- 搜索并发度限制为 5。
- 话题归一化后缓存 24 小时。
- 相同话题的进行中请求合并，避免重复调用。
- 直答解析失败自动重试 1 次。

### 8.2 部署策略

优先验证腾讯云 CloudBase 与知乎开放接口的延迟和稳定性，再决定是否保留其他部署方案。部署应在开发早期完成，确保后续视觉和演示工作建立在真实环境上。

### 8.3 安全与合规

- 凭证仅存部署平台环境变量。
- 前端不接触 App Key 和 Access Secret。
- 仅展示开放 API 返回的元数据和摘要，原文通过知乎链接打开。
- 明确标注“来源：知乎”和 AI 生成内容的参考属性。

## 10. 成功标准

### 10.1 产品标准

- 用户能在首页 10 秒内理解输入话题即可开始。
- 预生成话题能秒开完整地图。
- 实时话题先出现结构骨架，再逐个点亮资源。
- 用户无需登录即可完成核心流程。
- 任一节点失败时，地图仍可浏览且有明确恢复入口。

### 10.2 演示标准

演示应完整走通：打开预生成地图、查看节点层级、展开资源、跳转知乎、返回后看到已学状态、进入一级下钻，再输入一个新话题展示实时生成过程。

## 11. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 直答返回非法 JSON | 地图无法生成 | 清洗、结构校验、重试、保留可用节点 |
| 知乎搜索延迟或限流 | 节点无法点亮 | 并发限制、缓存、节点级重试 |
| 资源质量不稳定 | 地图可信度下降 | 相关性过滤、互动权重、预生成地图人工检查 |
| 部署环境延迟较高 | 演示等待时间过长 | 提前部署实测，优先使用缓存话题 |

## 12. 后续路线

首版稳定后，再考虑增加节点编辑、笔记与批注、多地图管理、收藏夹导入、账号体系与跨设备同步，以及更完善的移动端交互。后续功能必须服务于“从话题到可执行学习路径”，不能让生成和阅读主流程变复杂。
